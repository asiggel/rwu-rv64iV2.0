
Table \ref{tab:asDec05} lists every RV64I base integer instruction this core decodes (RV32I base set \cite{riscvisa01}, \cite{riscvisa02}, \cite{riscvisa03} plus the RV64I word-width and Zicsr/privileged additions), with the exact control-signal values produced by \texttt{as\_instr\_decode.sv} for each. FENCE/FENCE.I and the nine SYSTEM-opcode instructions (missing from earlier revisions of this table) are now included.

Legend:
\begin{itemize}
  \item Ins: Instruction short
  \item op: \texttt{instr\_opcode\_i}
  \item f3: \texttt{instr\_func3\_i}
  \item f7: \texttt{instr\_func7b5\_i}
  \item S: \texttt{mux\_resultSrc\_o} (0=\texttt{RES\_ALU}, 1=\texttt{RES\_MEM}, 2=\texttt{RES\_PC4}, 3=\texttt{RES\_CSR})
  \item W: \texttt{en\_dMemWr\_o}
  \item R: \texttt{en\_dMemRd\_o}
  \item B: \texttt{mux\_aluSrcB\_o}
  \item A: \texttt{mux\_aluSrcA\_o} (0=\texttt{SRC\_REGA}, 1=\texttt{SRC\_PC}, 2=\texttt{SRC\_ZERO})
  \item r: \texttt{en\_regWr\_o}
  \item j: \texttt{mux\_jump\_o}
  \item im: \texttt{sel\_immSrc\_o} (0=\texttt{IMM\_NONE}, 1=\texttt{IMM\_I}, 2=\texttt{IMM\_S}, 3=\texttt{IMM\_B}, 4=\texttt{IMM\_U}, 5=\texttt{IMM\_J})
  \item alu: \texttt{alu\_op\_o} (0..14, see Table~\ref{tab:asDec01}/the Internals list for the name mapping; shown as ``-'' where the ALU result is not used, i.e.\ the field holds the don't-care default \texttt{ALU\_ADD}=0)
  \item br: \texttt{br\_op\_o} (0=\texttt{BR\_NONE} .. 6=\texttt{BR\_GEU}, 7=\texttt{BR\_ALWAYS})
\end{itemize}
\texttt{trap\_illegal\_instr\_o}=0 for every row in this table by construction (they are exactly the valid encodings); see Table~\ref{tab:asDec01} and the Internals list (Section~\ref{sec:decfunc01}) for which \texttt{func3} values are \emph{not} listed here and therefore trap.

\noindent\footnotesize\textsuperscript{(1)}\,\texttt{ecall}, \texttt{ebreak},
and \texttt{mret} are indistinguishable from one another at the
\texttt{instr\_opcode\_i}/\texttt{instr\_func3\_i} granularity this table
is keyed on (all three: op=1110011, f3=000); \texttt{as\_instr\_decode}
does not need to tell them apart (all three get the same, shown, control
signals). The CPU top level distinguishes them by inspecting
\texttt{instr[31:20]} directly (\texttt{ecall}=\texttt{0x000},
\texttt{ebreak}=\texttt{0x001}, \texttt{mret}=\texttt{0x302}); see
Section~\ref{subsec:irqconcept}. Columns marked ``-'' hold their
module-default value, which is never consumed for that instruction (e.g.\
\texttt{mux\_aluSrcA\_o}/\texttt{mux\_aluSrcB\_o}/\texttt{alu\_op\_o} for
\texttt{jal}/\texttt{jalr}/SYSTEM: the register write-back value comes
from \texttt{RES\_PC4}/\texttt{RES\_CSR}, not the main ALU, and the
branch-target address is computed by a separate adder gated by
\texttt{mux\_jump\_o}, not by \texttt{alu\_op\_o}).\normalsize
